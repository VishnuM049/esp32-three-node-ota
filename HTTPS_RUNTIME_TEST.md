# HTTPS + Noise hardware run: three-node OTA succeeded, earlier edge rollback recorded

**Accurate scope:** A signed edge OTA succeeded on each edge through the controller's certificate-verified HTTPS upload and Noise relay; signed controller v10→v11 succeeded over HTTPS. Both v9 edges re-registered without manual power cycles on two controller-only resets and the subsequent v11 OTA reboot. These are bounded hardware observations, not a production-security audit. The earlier failed edge1 v8 first boot is retained below, not erased from the record. Original signed/Noise `main` has not yet been replaced; controller v8 full flash is retained locally under ignored, mode-0600 `private_keys/flash_snapshots/full_controller_*/` (unencrypted local backup, not an independently tested restore).

## 2026-10-28 controller USB / Mac TLS tests

- Physically identified USB controller MAC `20:50:0d:1b:64:d8`, classic ESP32 4 MB. USB flashed key-bearing **v10** experimental HTTPS build only after twice-verifying the controller v8 full flash in 64 KiB chunks and matching its signed v8 app in the OTA1 partition. Flash upload hash verified. This changes controller firmware and OTA selection; edge flash/NVS unchanged.
- Controller `/status`: `role=0 version=10 noise=1 tls=1 ota=unknown`. `ota=unknown` follows a USB bootstrap, **not** a signed v10 OTA valid boot. Certificate-verified Mac `curl --cacert private_keys/host_tls/server.crt https://192.168.4.1/no-upload` completed TLS handshake (expected 404). Wrong local trust anchor rejected (`curl` exit 60). Plaintext HTTP `POST /update` with a harmless one-byte body rejected (403). HTTP GET `/status` intentionally remains plaintext.
- Edges initially did not re-register unattended after controller reboot. Manual power cycles of **edge power only** restored simultaneous authenticated `edge1_secure=v7_ota2_... edge2_secure=v7_ota2_...`. This is **still not** automatic reconnection.

## First HTTPS → Noise edge1 OTA attempt: failed first-boot confirmation

- Exactly one HTTPS-upload attempt of the prepared, validly signed edge1 **v8** image: controller replied `Authenticated edge accepted signed image; rebooting`. New edge1 briefly appeared as **`v8_ota1` pending**, with status RTT ~10.09 seconds. Edge2 remained v7 valid.
- ~30 seconds later edge1 was observed **back on v7 `ota2`**. Sender printed `STOP: no confirmed healthy boot` and exited nonzero. Controller TLS/Ota minimum free heap after transfer was about **98,704 bytes**, stack margin around **10,688 bytes** as exposed by its loop-task status (not TLS task stack). These are diagnostic samples, not stability guarantees. No second upload or edge2 OTA was attempted.
- A Mac web-log process (`web_log/server.py`) was discovered running concurrently, polling the controller's synchronous `/status` every ~8 seconds; the sender also polled after acceptance every ~3 seconds. The single controller Arduino loop handles `/status` by synchronously opening authenticated Noise status sessions to BOTH edges, which can block for many seconds while edge1's first-boot code is trying to register to the controller's peer listener. **Starvation/timing is a hypothesis, not yet a proven root cause.** The status observation `v8_ota1` is not evidence that REGISTER_OK or `esp_ota_mark_app_valid_cancel_rollback()` succeeded. Logs from edge1 during its pending first boot are needed.

**The failed v8 was never resent.** The sender stopped; edge1 returned to v7 valid and was inspected via MAC-checked USB serial before using a freshly signed higher v9. Its serial log captured v9's `First-boot edge self-test waiting...` followed by `Authenticated registration passed; OTA image confirmed`. A Mac web-log poller was stopped; new senders allow a quiet 20–45-second first-boot window; v9 firmware rate-limits Wi-Fi reconnect nudges, proactively re-registers on re-association and allows up to 90 seconds for authenticated registration before rollback. These changes together succeeded. **The exact cause of the v8 rollback is still not isolated** (polling load vs timing vs other factors); do not claim any one fix was singly proven. Mac Wi-Fi was returned to its normal network after every status/upload check.

## Completed follow-up (same hardware run)

- Edge1 **v7→v9** (intentional skip of failed v8): verified HTTPS upload → pinned Noise relay → signed edge image accepted → serial-confirmed authenticated first boot → `edge1_secure=v9_ota2_`. Edge2 was temporarily unplugged for edge1 USB serial capture, not independently authenticated in that one-node snapshot.
- Edge1 stayed powered through **two controller-only USB resets** and re-registered under Noise without manual edge intervention: `v9_ota2` in controller status within ~27 and ~34 seconds. Serial recorded Wi-Fi loss and recovery. An ESP-IDF `wifi:sta is connecting` warning occurred during one rate-limited retry, but connectivity returned.
- After reconnecting the edge hub, controller status showed **edge1 v9 valid and edge2 v7 valid together**. Edge2 **v7→v8** succeeded with a 20-second quiet first-boot window and independently reported `v8_ota2`. Edge2 then **v8→v9** via a separate signed HTTPS/Noise update and reported `v9_ota2`. No edge was reflashed by USB for these updates.
- With both v9 edges continuously powered, **two further controller-only resets** produced the same authenticated simultaneous `edge1_secure=v9_ota2_... edge2_secure=v9_ota2_...` without touching edge power in ~26 and ~25 seconds.
- Controller v10 (USB bootstrap, `ota=unknown`) received exactly one separate **signed, key-free v11 OTA over pinned HTTPS**; HTTP replied `Signed image accepted; rebooting`. Independent status after reboot confirmed `role=0 version=11 noise=1 tls=1 ... edge1_secure=v9_ota2_... edge2_secure=v9_ota2_... ota=valid last_invalid=none`. A new verified-TLS handshake still worked on v11. This also observed unattended edge re-registration after a real **controller OTA reboot**, not only manual controller resets.
- On the final controller **v11**, a **one-byte HTTPS POST** to `/edge2` with matching-length/role but deliberately forged Ed25519 signature returned `403 Invalid developer signature`. A plaintext HTTP firmware POST still returned `403 Firmware uploads require verified HTTPS port 443`. Status before and after remained controller v11 valid and both v9 edges authenticated/valid. This is an early metadata-rejection test, not a full-image tamper or replay test.
- HTTPS controller minimum free heap observed after the failed v8 attempt ~98.7 KB, after successful edge2 OTA ~106.6 KB; after the controller v11 reboot its own new minimum was ~166.5 KB. Status stack margin describes the Arduino loop task, **not** the HTTPS server task. None of these numbers is a worst-case guarantee.

## Remaining gaps and presentation scope

- No packet capture yet proves absence of plaintext image bytes on the AP, though pinned HTTPS/Noise handshakes and actual success/rejection were observed. Mac→controller **read-only `/status` is still plaintext HTTP**; firmware POST on port 80 is rejected. Controller decrypts and re-encrypts between hops, so do **not** claim laptop→edge end-to-end secrecy from a malicious controller.
- No physical flash-extraction protection; TLS private key is in controller NVS and the **USB-only bootstrap image**, not in the key-free signed v11 OTA image. No full live Noise wrong-key/replay/tamper suite; no edge failure-rollback injection test; no HTTPS-task stack high-water measurement. Keep the v8 edge1 rollback caveat visible.
- Preserve the full v8 controller flash snapshot and generated TLS private key locally, ignored, mode 0600. Independent encrypted off-Mac backup and full image restore are still unverified. Do not publish snapshots, keys, or USB-bootstrap binaries. Newer demo versions must be compiled and signed locally before another one-shot presentation; old edge v8 and controller v9 artifacts are now obsolete on these boards.
