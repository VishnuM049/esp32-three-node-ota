# Authenticated controller–edge link: plan and security gates (PARTIAL HARDWARE TEST)

**Status (2026-10-28): USB BOOTSTRAP AND BOTH ENCRYPTED SIGNED EDGE OTAs WORKED; FINAL v8/v7/v7 STATE CONFIRMED AFTER MANUAL EDGE POWER CYCLES.** Controller v8 and both edges v7 reported valid, with both edge status requests authenticated simultaneously. The edges did **not** reconnect automatically after controller v8 reboot; manual unplug/replug was required. See `NOISE_RUNTIME_TEST.md` for observations and gaps. Application-level Ed25519 verification and earlier edge rejection tests were already hardware-proven; see `SECURE_OTA.md` and `ROLLBACK_TEST.md`. Keep `main` and proven signed/rollback branches and binaries intact. Work on `feature/noise-link` only. Never call the existing Mac→controller AP/HTTP traffic Noise-encrypted.

## Objective and exact scope

Encrypt/authenticate **controller ↔ each edge** OTA bytes and acknowledgements, enrollment/registration, and controller-queried edge status. A passive AP observer should not read OTA image contents on that hop; an active network peer must not impersonate either endpoint or alter/replay records. An edge must *not* accept plaintext `/update` after enrollment. Signed `OTA1` manifests, SHA-256 checking, role/version checks, and boot validation remain **independent requirements at the destination**; encryption does not replace them.

**Out of scope:** Mac → controller HTTP upload remains plaintext on the SAME demo AP. A passive AP observer can still recover the firmware from that upstream upload even if controller → edge is encrypted, so **do not claim confidentiality of the firmware from an AP observer overall** or end-to-end confidentiality. The experiment tests a protected *hop*, not a private whole delivery. USB serial, physical flash access, Wi-Fi metadata (IPs/timing/traffic length), and post-confirmation crashes are not protected. Static secrets stored in ESP32 flash are extractable without hardware Secure Boot/flash encryption; do not claim hardware-backed identity or eFuse anti-rollback.

## Cryptographic decision (gated on build/size feasibility)

Use a maintained **Noise implementation**, not a home-made handshake built from `crypto_kx` calls. Candidate: [Noise-C](https://github.com/rweather/noise-c) (MIT-licensed reference C implementation), protocol **`Noise_KK_25519_ChaChaPoly_SHA256`**: the controller and each edge have distinct pre-provisioned static X25519 keys and know the correct remote public key before handshake. Fresh ephemeral keys and directional transport cipher states come from the library. Controllers must pin edge1 and edge2 separately; edges pin only the controller. Pin exact bytes, not an unauthenticated Wi-Fi MAC/IP or name. Bind fixed application context + edge role to the Noise prologue; no protocol fallback or cipher negotiation. Validate the library's KK support and Xtensa/Arduino build, published test vectors, measured flash/RAM overhead and license **before** integrating it. If Noise-C does not fit the 1.25 MB OTA slot or cannot run correctly, stop and revise the plan explicitly; do not silently substitute custom crypto while calling it Noise KK.

Provisioning is separate from the Ed25519 firmware-signing key. Generate **three different** X25519 static identities locally with a reproducible provisioning tool. Keep private material under ignored `private_keys/noise/`; only the **one-time USB bootstrap builds** contain a role-specific private header and write that key into a separate NVS namespace (`ota-link/identity`) without replacing an existing different key. Later OTA builds include **public pins only**, load the local private key from NVS at boot, and verify its derived public key against their pinned local identity. The Mac→controller hop remains plaintext: **a firmware OTA image containing an embedded static private key would permanently compromise the link**. Both the build and host sender scan the actual OTA `.bin` for all provisioned private-key byte strings and refuse one that contains any; the OTA build excludes bootstrap source entirely. This scan is defense in depth, not a formal proof of secrecy. Never commit private keys, USB bootstrap binaries, merged flash images, or serial dumps of secrets. Refuse to overwrite a key and prove the intended role/pins before any device flash. NVS is **not encrypted at rest** here: physical flash extraction still breaks the demo trust boundary.

## Transport and firmware integration

1. Keep laptop → controller `/update`, `/edge1`, `/edge2` for the signed transport demonstration; document that hop as **plaintext**. On the controller, replace plaintext `WiFiClient` forwarding to an edge with a freshly authenticated Noise session to the pinned role's edge. On an edge, require a completed authenticated controller session **and a fresh authenticated transport record from the controller** before accepting a manifest or writing a single OTA byte. KK's first handshake packet can be replayed; it must have **zero side effects**. The responder's fresh ephemeral contribution and controller's first transport record provide proof of the new session before any update state change. Do not expose a plaintext edge `/update` fallback in the final firmware.
2. Use one TCP connection per Noise session; frame Noise handshake and transport records with a bounded 2-byte length prefix, reject zero/oversized/truncated frames, and cap plaintext records at 1025 bytes (1 command byte + up to 1024 data bytes, then +16-byte AEAD tag). Let the library maintain independent directional nonces; never reinitialize counters mid-session or reuse ephemeral keys. Fail closed on AEAD/tag/handshake errors; discard partial updates with `Update.abort()` and close the connection. Authenticate the exact role/identity before trusting an IP learned from Wi-Fi registration.
3. Relay the original **unchanged** 109-byte signed OTA manifest inside the encrypted application protocol, then numbered/ordered image chunks and an authenticated final reply. Stream decryption and SHA-256 on the edge; still verify signature, role, signed length, strictly increasing version and full image hash **before `Update.end(false)`**. Never buffer the whole ~1 MB image in RAM. Controller should treat failed/absent authenticated edge acknowledgement as failure, not as success.
4. Replace plaintext edge registration with an authenticated Noise session. A bounded untrusted role hint may select which pinned edge key to test, but must not update `edge1`/`edge2` until that role's handshake succeeds; role and controller/edge direction must be bound to the session. Controller-observed edge status should use a separate authenticated connection. The direct plaintext edge diagnostic endpoint must be removed or explicitly documented as a non-confidential exception; USB serial can be used for debugging instead.

### Draft wire contract to preserve during implementation (not yet running)

- `Noise_KK_25519_ChaChaPoly_SHA256`, exact prologue ASCII `ESP32-OTA-LINK-v1/edge1` or `ESP32-OTA-LINK-v1/edge2` on **both** peers. Reuse the pattern with fresh ephemeral keys on *each* TCP connection. Controller→edge initiates for update/status; edge→controller initiates for registration. Controller port 80 remains laptop-facing HTTP; controller port 8081 accepts encrypted registration; edge port 8080 accepts **only** Noise-framed sessions.
- Each message on TCP is `uint16_be(ciphertext_or_handshake_length) || exact message bytes`; hard caps: handshake message 512 bytes, transport message 1041 bytes (1025 plaintext + 16-byte tag). No zero-length, oversized, short, or trailing bytes accepted. No initial application payloads in KK handshake; **wait for an authenticated post-handshake transport record** before changing any registration or OTA state. For controller port 8081 registration only, one *untrusted* role-hint byte `0x01`/`0x02` precedes the framed handshake to select a pinned remote public key; controller must not trust the hint/IP until KK completes with the corresponding role prologue and a valid encrypted REGISTER record.
- Application plaintext within authenticated transport records (types are one byte): `0x01 REGISTER` (empty body), `0x02 REGISTER_OK` (empty), `0x10 UPDATE_BEGIN || OTA1_manifest[109]`, `0x11 UPDATE_DATA || image_chunk[1..1024]`, `0x12 UPDATE_COMMIT` (empty), `0x13 RESULT || code:u8` (0 accepted; nonzero rejected), `0x20 STATUS_REQUEST` (empty), `0x21 STATUS_REPLY || role:u8 || version:u32_le || ota_state:u8 || min_heap:u32_le || stack_margin:u32_le` (15 bytes). No other types, fields or trailing bytes. The signed manifest supplies exact image size; count decrypted data bytes and reject overflow or missing bytes before commit. A malformed sequence/record aborts the inactive OTA slot and closes the connection. The endpoint's signed version/role/hash checks remain authoritative. An accepted response is only a transfer result; the host must independently check version/boot state after reboot and never auto-retry ambiguous uploads.
- These are **draft application framing decisions**, not extra Noise primitives. Keep upstream Noise-C's own handshake processing, key derivation, counters and AEAD unchanged. Tests may drive a revision of the draft **before any board is flashed**; if wire format changes, update this document and both endpoints together. No protocol downgrade or plaintext fallback in the final receiver.

### Current integration candidate (compile-tested; partial hardware test in `NOISE_RUNTIME_TEST.md`)

`noise_firmware/NoiseLink.h` and `NoiseLink.cpp` wrap the pinned Noise-C KK handshake and bounded encrypted framing; `noise_firmware/noise_firmware.ino` retains the Ed25519 receiver/hash/rollback logic but replaces controller→edge forwarding, registration, and edge status with Noise sessions. Edges expose only encrypted port 8080 (no plaintext HTTP listener); controller port 8081 accepts encrypted registration while controller port 80 remains **plaintext** for laptop requests. Edge first-boot confirmation waits for authenticated controller registration (30-second timeout, otherwise attempts rollback). `IdentityStore.cpp` loads/pin-checks a 32-byte NVS identity; the **bootstrap-only** `BootstrapIdentity.cpp` provisions it once. `build_noise_firmware.sh --bootstrap` produces USB-only key-bearing candidates; `--ota-targets` produces **key-free** version-increased images, signs/locally verifies them with Ed25519, and rejects any binary containing a provisioned raw X25519 private key. MAC-checked USB bootstrap and three one-shot signed OTAs have occurred; see `NOISE_RUNTIME_TEST.md` before attempting any further update. Generated role-specific scratch sketches and all app artifacts remain ignored under `noise_experiments/`; **bootstrap artifacts contain device secrets and must NEVER be shared or sent by OTA**.

The role-specific loop stack override and deferred OTA-verification hook are **strong** ELF symbols; the edge images' linked strings contain no plaintext HTTP `/update` or legacy registration command. Runtime minima do not rule out other heap fragmentation, stack exhaustion, RNG problems, or wireless failures.

## Migration: avoid a false encryption claim

At migration time edge v4 and controller v5 did **not** speak Noise. If the controller disables plaintext before the edges migrate, edge OTA stops; if plaintext fallback remains, the link is not fail-closed. The simplest, most honest classroom migration is a **one-time USB bootstrap of all three** to role-specific encrypted receivers, with MAC/flash-size verification and recovery binaries kept offline. Then demonstrate **newer signed OTA images through the Noise-protected controller→edge links** and independently verify each destination's version and first-boot state. Choose new distinct version numbers above installed values (controller >5, edges >4; reserve v6 controller as the historical deliberately failing test), and keep the new binaries/manifests ignored. Do **not** USB-flash or send anything until a per-role bootstrap and recovery checklist is reviewed. A staged signed-OTA migration with temporary plaintext support is an alternative only if separately designed, visibly labeled transitional, tested, and removed from the final receiver.

## Test gates (record actual results, never infer them from compilation)

- **Offline/library:** basic cross-compilation, OTA factory-only size check, two desktop KK vectors and role-key provisioning tests **passed**, and full role-specific integration size checks **passed**; registration and both edge OTA flows ran on devices; unattended post-controller-reboot re-registration **did not occur** in this run. Compare a known KK vector on a device only after non-releasable probe recovery is planned. Inspect library license/port changes and worst-case RAM/heap under actual packet traffic. Reject wrong remote key, malformed/truncated/tampered handshake, and tampered/duplicated/reordered transport records. A replayed initial KK packet may be accepted as a handshake step but must cause **no update or registration side effect** and cannot authenticate replayed transport from an old session. Test this, plus oversized frames, nonce exhaustion, and interrupted transfer. Verify no private key appears in `git status`, logs or tracked artifacts.
- **Hardware bootstrap:** verify three MAC addresses, back up proven signed/rollback binaries, then USB-bootstrap each role with its unique key. Confirm authenticated registration/status, no plaintext edge `/update` or direct unauthenticated update, and failure with wrong role/peer/key. Do not power-cycle/reflash a board merely to hide a test failure.
- **Hardware OTA:** from laptop send new **signed** role-specific images once; capture status before and after. On the controller–edge hop inspect packet capture only to the extent practical: no raw firmware bytes or manifest may appear in cleartext, but IP/length/timing are not hidden; host→controller still clear. Tampered ciphertext and altered signed image must not select a new boot slot. Test unexpected TCP disconnect/rejoin and confirmed first boot, and record whether rollback works on each edge separately.
- **Release claim:** only after all three encrypted receivers reject plaintext, both links pass authentication/encryption/replay negatives and signed OTA works through them may we call the controller–edge OTA hop Noise-protected. **Do not claim end-to-end encrypted host→edge OTA, physical key protection, or full Noise implementation before protocol-conformance testing.**
